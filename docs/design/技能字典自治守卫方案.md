# 技能字典自治守卫(dict-guard)设计方案

> 状态:**实施中**(2026-08-21 方案批准;PR-A 机制层已合并 #370,PR-B 评估层评审稿,PR-C/D 接口与前端待排)
> 背景:技能字典(SKILL_STOPWORDS/SKILL_ALIAS/skill_whitelist.yaml)是幻觉防控第三道防线载体,现行治理全靠人工批次补词(P1~P9 批次注释即变更日志),闭环周期长、长尾覆盖不足。
> 关联:《岗位名LLM审查设计方案》(同构先例,原则移植)、AGENTS.md §4.1 算法红线、设计文档 §6.3 三道防线

## 1. 背景与问题

### 1.1 现状

技能字典由三部分组成,全部 import 时静态加载、无热加载:

| 表 | 位置 | 规模 | 用途 |
|---|---|---|---|
| `SKILL_STOPWORDS` | dictionary_data.py | 156 条 | 命中即从抽取结果删除(行业/泛词/业务词) |
| `SKILL_ALIAS` / `TOOL_ALIAS` | dictionary_data.py / dictionary.py | 130+68 条 | 别名→标准名归一 |
| `SKILL_WHITELIST` | configs/skill_whitelist.yaml | 605 条 | 保护(免剥壳/免判噪)+分类 |

**局限**:停用词过宽会误杀真实技能(如「微」⊂「微信小程序」——停用词优先于白名单是有意设计);漏拦噪音则污染图谱;每次调整都需人工扫描→编辑源码→补测试→PR→重启容器。

### 1.2 目标

每日定时用**规则候选生成 + LLM 结构化评估**图谱技能数据,对字典做两类调整:
- **加过滤**(add_stopword):拦截图谱长尾噪音;
- **解误杀**(remove_stopword / protect_whitelist):发现停用词误伤并放行受影响技能。

## 2. 定位与原则

**定位**:幻觉防控第三道防线的**运行时自治层**,不替代静态字典——静态字面量仍是单一事实源基线,动态层是可审计、可回滚的叠加。

**原则**(对齐岗位名 LLM 审查方案):
- LLM 增强 + 规则优先 + 门控 + 失败降级;
- **高风险变更不自动写规则库**:分级生效(§5);
- 全量审计(DictChangeLog)+ 一键回滚;
- prompt/门禁阈值/分级规则属算法核心,**变更须张恺天 review**。

## 3. 总体架构

```
ETL 主管线(阶段16,聚合/快照之后,继承当日幂等锁)
 → 候选生成(纯规则,零 LLM 成本)
    a. 图谱长尾可疑技能(REQUIRES≤1 + 白名单外 + 非停用词)
    b. 停用词误杀检测(近7天 JD 语料:停用词 ⊂ 白名单技能名 且两者均命中)
    c. 每类 top-N(runtime_config.dict_guard_max_candidates=20)
 → LLM 单候选评估(call_with_fallback 异步链,DictGuardDecision Pydantic 强校验
    {action, term, reason, confidence};单条失败跳过计数,全败告警不阻塞管线)
 → 硬门禁 hard_gate(一票否决,先于分级):
    add_stopword 与白名单/别名标准名/工具别名/软技能白名单互斥
    remove_stopword 必须指向现行停用词(静态移除走 git 固化流程)
    protect_whitelist 必须指向当前被拦且未受保护的词
 → 影响面模拟(图谱同名节点数 + JD 原文命中数)
 → 分级 tier_for:
    auto     仅 add_stopword:过硬门禁 + 影响面≤50 + confidence≥0.8
             → 写动态过滤层 + DictChangeLog + scoped 清理同名 Skill 节点
    proposal 其余一律(remove/protect/超影响面/低置信)
             → dict_proposals 表 pending 进审核池(同 term+action 待审去重)
 → 报告 reports/dict_guard_{date}.json;auto 生效或 LLM 全败时 webhook 告警
```

## 4. 动态过滤层(机制核心,PR-A 已合并)

- 存储:`backend/configs/skill_filters_dynamic.json`(gitignore+.example,同 runtime_settings 模式);
- 加载:`services/extraction/dynamic_filters.py`,30s TTL 热生效(移植 weights.py 缓存模式),原子写盘,缺失/损坏按空层处理;
- **唯一接线点** `dictionary.is_noise_skill()`,判定顺序:
  1. 动态保护最先(解误杀通道,压过静态停用词);
  2. 静态停用词;
  3. 白名单/别名标准名保护;
  4. 动态停用词(纵深防御:即使门禁被绕过,白名单词也不会被动态拦截);
  5. 原启发式(G1-G5 全链路经此单一入口自动生效,G3/G4 下轮 ETL 自动按新字典重滤旧快照);
- 审计:JSON 文件是运行时生效态,`dict_change_logs` 表是完整审计链(source=auto/manual/rollback),稳定条目经人工确认后固化回 git 字面量。

## 5. 分级生效的风险不对称依据

拦噪音(add_stopword)是收紧动作,最坏后果=暂时少收录一个长尾词,且有影响面阈值兜底;放行类(remove/protect)会让历史已滤噪音回流,污染 must 聚合与匹配。故仅前者可自动,后者必须人工批准。

## 8. 配置(runtime_config,重启生效)

| 键 | 默认 | 说明 |
|---|---|---|
| `dict_guard_enabled` | true | 总开关,false 时阶段直接跳过零 IO |
| `dict_guard_auto_impact_threshold` | 50 | 自动生效影响面上限(图谱节点数) |
| `dict_guard_min_confidence` | 0.8 | 自动生效最低 LLM 置信度 |
| `dict_guard_max_candidates` | 20 | 每类候选上限(控 LLM 成本,每日 ≤40 次) |
