# 岗位职能域治理设计（2026-09-01）

> **性质**：算法设计说明（What & Why），配套验收记录见 `docs/reviews/域治理算法复核包_20260901.md`。
> **触发**：用户实测发现 TypeScript工程师 被归入「系统可靠性」，溯源岗位域聚类质量后发起全域治理。
> **归口**：算法红旗（聚类/归类口径），改动须 zkt 知会；本方案已由负责人 2026-09-01 拍板验收（基准 100%/frozen2）。

## 1. 背景与问题

图谱岗位职能域（前端/后端/算法等超节点分组）此前由「岗位-岗位投影图 Leiden 聚类」全量划分，实测暴露四类问题：

1. **垃圾岗污染**：国际源单条 JD 产出雇主名当岗位名（Clay/GSBOA）与非技术职业（司机/前台），「项目管理」域 15 席中 13 席为垃圾岗
2. **微簇噪声**：TypeScript工程师(freq=1)+系统可靠性工程师共享 2 技能成 2 人微簇，LLM 按代表岗命名为"系统可靠性"域
3. **桥梁岗语义缺失**：大模型算法工程师(376)/Python(290)/DevOps(148) 高频岗被 Leiden 撕成单点落「通用与其他」
4. **静默错配**：全链路无人工验收口径，域归属只进容器日志，用户无法追因

## 2. 架构：骨干域 + 归类制

替代"全员聚类"（75 岗一起玩社区博弈），分两层：

```
┌─ 骨架层（freq≥3 高置信岗进骨干 Leiden）─┐
│  骨干聚类 → pins 簇覆盖 → <3 人簇降级     │
└──────────────┬───────────────────────┘
               │
┌─ 归类层（freq<3 / 降级岗带弃权归类）──┐
│  pin 覆盖 → 阈值归类（≥3.0 且领先1.3×）│
│  → 弃权落「通用与其他」              │
└────────────────────────────────────┘
```

- `split_backbone(freq≥3)`：骨干门频；探针实证 freq≥10 切掉前端细分族致枢纽孤立
- `demote_small_clusters(<3)`：微簇降级进归类池；freq=1 岗结构上凑不出"域"，微簇域从舞台消失
- `resolve_fringe`：带弃权的最近域分类——连接强度 ≥3.0 且 ≥次优×1.3 才归入，否则诚实弃权
- `PINNED_DOMAIN_ANCHORS`（34 条）：治理声明覆盖拓扑（桥梁岗/基准收口/池子压缩/强制弃权 GENERAL_PIN）

## 3. 可解释性（本次治理的核心增量）

**每个岗位落图三个属性**（治理页逐岗可查）：

| 属性 | 含义 | 取值 |
|---|---|---|
| `domain_source` | 归类依据 | backbone / pin_cluster / pin / attach / leftover_pin / general_pin / below_affinity / not_dominant / no_edges / leftover_no_edges |
| `domain_score` | 归类亲和度 | 阈值归类岗的 Σ 连接强度（治理指派/骨干为 null） |
| `domain_alternative` | 次优域得分 | 多域拉扯诊断用 |

配套：
- **LLM 成员自审**（`cluster_membership` 决策记录）：每次域同步后逐域裁决内聚性，可疑成员落 proposal/R2 进审批页（只检测不改写；本机实证 flag 3 条全为真问题）
- **域治理页** `/admin/graph-governance`：语义域成员清单 + 来源分布 + 基准得分 + 后台重同步
- **归因闭环**：任何岗位 → 治理页 → 域 → 成员明细 → 来源 + 得分 + 弃权原因

## 4. 基准与验收

`data/golden_set/position_domain_eval.jsonl`——**共成员关系基准**（与 LLM 域名解耦，锚点=高频稳定岗），72 条断言（`expect=domain` 同域 / `expect=general` 弃权）。当前 **frozen4**（2026-09-02 域细分阶段 1+2，见 §8）。

| 口径 | 治理前 | 08-31 治理后 | 09-02 细分后 |
|---|---|---|---|
| 严格通过率 | 55.6% | **100%**（72/72，frozen2） | **100%**（72/72，frozen4） |
| pairwise F1 | 0.552 | 0.791 | 0.799（frozen4） |
| 域结构 | 15 碎域（4 污染） | 5 语义域 + 弃权池（29 岗） | 5 骨干语义域 + 4 显式语义域 + 弃权池（19 岗） |
| 垃圾岗 | 30 | 0（停用词防复发） | 0 |

验收经历：全员聚类(55.6%) → 骨干+归类(76.4%→98.6%→100%)；`evaluate_position_domains.py` 支持 `--min-accuracy` 门禁，`--llm-name` 语义域名。

## 5. 关键决策留痕

| 决策 | 依据 | 回退点 |
|---|---|---|
| 骨干门频 freq≥3 | 探针实证 ≥10 切前端细分族致枢纽孤立 | CLI `--backbone-min-freq` |
| 归类门槛 3.0/1.3× | 2.0 被 nice 共享堆砌穿透（弃权行准确率 63%） | CLI `--attach-min-affinity/--attach-dominance` |
| GENERAL_PIN 语义 | share 探针：垃圾岗连接证据无差别指向枢纽域，拓扑不可分 | 改常量删除即可 |
| 簇级归类否决 | 微簇池化 2/14、人均亲和度 11/26（负例高于正例、分布重叠） | 记录归档，P3 嵌入方向 |
| 弱锚定 5 行 | 全栈=前后端均衡(1.94 压后端)、网络工程师=近随机(1.02) | 改 pin 单条回退 |

**复核（2026-09-01）**：弱锚定 5 行异步复核通过（全栈/鸿蒙/C++/AI基础设施/网络工程师全部维持原断言），note 附拓扑证据，基准升 frozen2。

## 8. 显式语义域细分（2026-09-02 阶段 1+2，已落地）

**动机**：通用与其他桶（29 岗）为跨域桥梁岗——拓扑探针实证对枢纽域连接 22-29 » 域内 0.6-7.2，Leiden/亲和度归类失效（08-31 结论维持）；但 **LLM 语义归类探针**（position_classify，3 轮 99 次，清单内选唯一类目+硬门防自创）在候选清单提供新域名后，13 岗以 0.85-0.98 高置信选择新域——「拓扑不可分」的真相是「清单缺类目」。职能域的本质是职能语义而非技能拓扑，拓扑与语义为互补信号（拓扑=连接证据硬门，LLM=语义归类器，人工审批=最终把关）。

**机制**：`sync_position_domains.py` 新增 `SEGREGATED_DOMAINS` 显式域清单——成员直接归入显式域（`domain_source=domain_pin` 落图可勾稽），不触碰骨干 Leiden；曾被 GENERAL_PIN 弃权的成员（SAP集成/Murex应用/AI与数据系统/产品经理）弃权声明随语义域成立撤销。纯治理声明层，可单点回退（清空清单 + 断言回滚 + 重跑 sync，约 10 分钟）。

**4 个显式语义域（11 岗阶段 1 + 3 岗阶段 2 归既有骨干域）**：

| 显式域 | 成员 | LLM 探针置信 |
|--------|------|-------------|
| 网络安全 | 网络安全工程师、移动网络安全工程师 | 0.98 / 0.92 |
| AI应用与智能体 | GenAI/AgenticAI、AIGC抽卡师、AI与数据系统、创始工程师 | 0.95 / 0.9 / 0.75 / 0.65-0.6 |
| 企业应用与系统 | SAP集成、Murex应用、People应用、PACS与企业影像管理员 | 0.9 / 0.75 / 0.6 / 0.7 |
| 产品与项目管理 | 产品经理、项目经理 | 0.85 ×2 |

**结果**：域 6 → 10，通用桶 29 → 19 岗（非 IT 交叉与 LLM 摇摆岗诚实保留弃权）。基准 frozen2 → frozen4（断言同步 11 行 general→domain 互锚），评测 100%（72/72）/ pairwise 0.799。**算法复核**：复核包 `docs/reviews/岗位域基准复核包_frozen4_20260902.md`，知会 issue（@zkt-sky）。

**阶段 2 留通用观察**：游戏开发（名实不符）、系统可靠性/开发者体验/AIGEO（LLM 摇摆 ≤0.6）——待真实 JD 增长后复核，pin 可撤销。
