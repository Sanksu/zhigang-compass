# 岗位分类体系评估与优化方案

> 性质：设计类评估文档（评估报告 + 优化方案）
> 关联代码：`backend/app/services/extraction/dictionary.py`（岗位名归一化）
> 关联数据：PostgreSQL `jd_raw` 全量抽取记录 → Neo4j `Position` 节点
> 更新日期：2026-08-08

---

## 1. 背景与目的

岗位输出分类体系由 `normalize_position_name`（`backend/app/services/extraction/dictionary.py`）承载：LLM 抽取的 `position_name` 经关键词族 / 后缀剥离 / 英文翻译归一化后，作为 `Position` 节点入图（`aggregation.py` 全量聚合写回）。体系质量直接决定图谱岗位节点、全景图与匹配检索的可用性。

本报告基于**真实库全量数据**评估现有分类标准的逻辑性、一致性与实用性，识别归类错误、层级混乱、定义模糊与类型缺失问题，并给出 P0 / P1 / P2 三级优化方案

## 2. 评估口径与数据现状

### 2.1 评估数据

- 数据源：PostgreSQL `jd_raw` 全量 3096 条抽取记录，527 个原始岗位名
- 处理链路：`normalize_position_name`（生产函数实测，非推断）→ Neo4j `Position` 280 个节点
- 归一化效果（现状）：527 个原始岗位名 → 271 个归一化结果（3069 条），27 条被过滤（实习/泛词）

### 2.2 图谱岗位频次分布（280 节点）

| freq 区间 | 节点数 | 占比 |
|-----------|-------|------|
| 0（孤儿节点） | 2 | 0.7% |
| 1（长尾碎片） | 202 | 72.1% |
| 2-5 | 50 | 17.9% |
| 6-20 | 13 | 4.6% |
| 21-100 | 5 | 1.8% |
| ≥101（头部大桶） | 8 | 2.9% |

**核心结论**：freq=1 的长尾碎片占图谱 72.1%，分类实用性被碎片噪声严重稀释；同时头部 8 个岗位（算法/软件/前端/Java/后端/全栈/数据分析/Python）聚合了 69% 的 JD 记录，粒度失衡

## 3. 分类体系问题分析

### 3.1 岗位归类错误（实测验证）

| 输入岗位名 | 实际归一化 | 问题根因 |
|-----------|-----------|---------|
| SailPoint 顾问 | 算法工程师 | `AI` 关键词子串误匹配（sailPoint 含 "ai"） |
| Web & Mobile Automation Test Engineer | 前端开发工程师 | 英文测试岗含子串 "web" 被前端族吸走 |
| 网络 SRE 工程师 | 运维工程师 | 英文翻译层 `sre` 子串匹配，优先于中文 "网络" |
| 前端采购经理 | 前端开发工程师 | 采购职能岗被 "前端" 关键词吸走 |
| 网络安全工程师 / Security Engineer | 网络工程师 | "网络" 关键词把安全岗吸入网络族 |
| 产品经理 / 项目经理 / 数据工程师 | 产品 / 项目 / 数据 | 剥后缀后核心词成碎片，无对应族 |
| 董事总经理 | 董事总 | "总经理" 被误剥 "经理" |
| Founding Engineer | 创始 | 映射后再次剥后缀成碎片 |
| 数据科学家 | 科学家 | 并入笼统 "科学家" 桶 |
| DevOps 高级工程师 | DevOps | 无 DevOps 族，剥后缀残留英文词 |

**根因定位**（`dictionary.py`）：
1. `_POSITION_KEYWORDS` 使用子串匹配，短关键词 `AI` / `web` 必然误伤
2. `_POSITION_SUFFIX_RE` 剥后缀后，残留碎片（产品/项目/数据/客户/研究/知识/系统/创始/董事总 等）既不在 `_POSITION_STOPWORDS`（仅 7 词）也不在关键词族，直接放行入图
3. `_translate_en_position` 对含中文的岗位名也执行英文子串匹配，把中文标题内嵌缩写（SRE/BI/EDC 等）劫持

另存在 **8 个纯英文岗位原样入图**（Manager, Logistics、Legal Technology & Contract Management Systems Administrator 等）与 **22 个纯技术名词当岗位**（SQL/C/FPGA/KDB/EDC/DFT/PostgreSQL/PyTorch/Snowflake/BI/Agent/OpenShift/MLOps/Power Automate/SAP BTP 等），后者实为技能名而非岗位名

### 3.2 分类层级混乱

1. **无职业大类层**：280 个节点全平级，"科学家"(77) / "顾问"(30) 兜底族与 "Java开发工程师"(267) 同层，粒度从算法工程师(587) 到碎片 "需求"(1) / "计划"(1) 跨度极大
2. **顶部大桶粒度失配**：算法工程师(587) 吞并 AI 应用工程/ML/NLP/CV/推荐/风控/自动驾驶/机器人/量化交易/AI Infra/MLOps 等全部 AI 相关岗位；前端开发工程师(313) 还吸入自动化测试与保险系统开发岗（Guidewire 开发工程师）
3. **聚合不清理孤儿**：`aggregation.py` 的 `MATCH ... SET` 只更新已存在节点，不删除废弃节点，"微流控""房地产技术副总裁"（freq=0）残留

### 3.3 类别定义模糊

- **数据域五马分尸**：数据分析师(177) / 大数据开发(12) / 数据工程(3) / 数据治理(2) / 数据管道(1) / 数据处理(2) / 数据录入(2) 各自为政，"数据工程师" 却归到碎片 "数据"，边界无统一规则
- **DevOps/平台域分裂**：DevOps(10) / 站点可靠性(3) / 平台(2) / MLOps(1) / LLMOps平台(1) / Kubernetes 服务(1) / Azure 云(1) / OpenShift(1)
- **安全域分裂**：安全(2) / 安全运营(3) / 安全运营中心(2) / 攻防安全(1) / 应用安全工程(1) / IAM 安全(1) / 产品安全(1)，且 "网络安全工程师" 被并入 "网络工程师"
- **科学家/顾问/研究员兜底族**：77+30+11+1 条被粗粒度合并，内部岗位差异巨大（数据科学家 vs 计算化学科学家 vs 决策科学家）

### 3.4 重要岗位类型缺失

- **产品经理 / 项目经理**：`_EN_POSITION_MAP` 有映射，但中文归一化把它们剥碎成 "产品/项目" 碎片，无独立族
- **数据科学家**：并入 "科学家" 桶，无独立族
- **安全工程师族**：完全缺失
- **DevOps / 平台工程师族**：完全缺失
- **数据库/DBA 族**：完全缺失
- **技术栈细分不平衡**：仅前端族有 React/Vue/Angular/鸿蒙/小程序/移动 细分，后端/算法/数据无对应细分维度

## 4. 优化方案

### 4.1 P0：修复确定性缺陷（归一化逻辑）

**P0-1 碎片词二次过滤**

- 扩充 `_POSITION_STOPWORDS`，覆盖实测碎片：产品/项目/数据/客户/研究/知识/系统/工程/结构/数字/运营/平台/安全/投资/风险/控制/计划/需求/精算/销售/客服/招聘/网页/客户端/逆向/集成/空间/机械/电气/现场/部署/工艺/定价/服务器/经理/创始/董事总/分析
- `_normalize_base` 剥后缀后对残留 core 再做一次 stopwords 校验（当前仅在返回后校验一次）
- 预期效果：消除约 40 个碎片节点、影响约 60 条记录，长尾从 202 缩至约 160

**P0-2 英文翻译 CJK 守卫**

- `_translate_en_position` 入口对含 CJK 字符的岗位名直接跳过英文子串匹配
- 预期效果：消除 "网络 SRE 工程师" 被 `sre` 翻译劫持、"SailPoint 顾问" 被 `ai` 劫持等混合标题误归类

**P0-3 修短关键词误伤**

- 算法族关键词 `AI` 移除，替换为精确形式（ai工程师/ai 工程师/ai 工程/ai agent 等），保留 `人工智能`
- 预期效果：消除 "SailPoint 顾问" → 算法工程师 的确定性误归类

### 4.2 P1：新增岗位族（归一化逻辑）

| 新增族 | 关键词 | 标准名 |
|-------|-------|-------|
| 产品经理 | 产品经理 | 产品经理 |
| 项目经理 | 项目经理 | 项目经理 |
| 创始工程师 | 创始 | 创始工程师 |
| 网络安全工程师 | 安全/攻防/渗透/威胁/IAM/SOC | 网络安全工程师 |
| DevOps 工程师 | devops/sre/站点可靠性/平台工程/mlops | DevOps工程师 |
| 数据科学家 | 数据科学家 | 数据科学家 |
| 数据库管理员 | 数据库/dba/oracle/mysql/postgresql/snowflake | 数据库管理员 |

配套调整：
- `_EN_POSITION_MAP`：`data scientist` 映射由 "数据分析师" 改为 "数据科学家"（语义更准确）
- 网络安全族置于网络族之前，避免 "网络安全" 被 "网络" 吸走
- 新族标准名自动纳入 `position_align.py` 的 `_STANDARD_NAMES`（语义对齐不参与，无冲突）
- **数据工程族补充**（P0-1 防丢真实岗位）：`_POSITION_STOPWORDS` 新增 "数据" 会把 "数据工程师 / 数据工程负责人" 剥成碎片后过滤为空（真实岗位丢失）。故在 大数据开发 族补充关键词 `数据工程`（与 `_EN_POSITION_MAP["data engineer"] → 大数据开发工程师` 一致），属于 P2 数据域统一方案 (a) 的提前落地
- **移除前端族短关键词 `web`**：子串匹配会误吸 "Web & Mobile Automation Test Engineer" 等英文测试标题；中文 web 标题（web前端/web开发）已由 "前端" 关键词覆盖，移除后不再误归前端

### 4.3 P1：清理技术名词节点与孤儿节点（数据操作）

- 归一化结果若命中技能白名单（`SKILL_WHITELIST`，592 项），视为"技能被抽成岗位"，返回空串不入图
  - 覆盖 SQL/C/FPGA/PyTorch/OpenShift/Agent/Snowflake 等 22 个技术名词节点
  - 大小写经 `_SKILL_WHITELIST_LOWER` 统一后比较（白名单含 "AGENT"/"Agentic AI" 等变体）
- 孤儿节点（freq=0，聚合只 SET 不清理的残留）需一次性清理脚本处理，建议复用 `scripts/cleanup_position_names.py` 的 `--dry-run` 模式先行预览

### 4.4 P2：可选优化（需产品决策）

- **算法工程师大桶边界**：587 条是否拆分为模型研发/应用工程/机器学习，取决于产品定位
- **岗位大类层**：依赖 `occupation_align` 骨架，为 `Position` 增加 category 属性（技术研发/数据/AI/产品/安全/职能 等），解决层级混乱
- **数据域统一**：数据工程师/数据工程 归入 大数据开发工程师 或独立数据工程族
- **技术栈细分扩展**：后端/算法/数据 增加与前端对等的细分维度

## 5. 实施与验证

### 5.1 实施范围（本次）

- `dictionary.py`：P0-1 / P0-2 / P0-3 + P1 新增族 + 技能词白名单冲突检测
- `tests/extraction/test_dictionary.py`：更新受影响断言 + 新增回归用例
- 全量数据验证：对 3096 条抽取记录跑新旧归一化对比，量化碎片减少与归类改善

### 5.2 验证方法

1. 单测：`uv run python -m pytest tests/extraction/test_dictionary.py`（在 `backend` 目录）
2. 全量对比：临时脚本读取 `jd_raw` 全量 `position_name`，对比新旧 `normalize_position_name` 输出，检查碎片节点减少数与头部族变化
3. 图谱重建（数据操作，需确认后执行）：重跑聚合并清理孤儿节点，验证 280 → 目标节点数

### 5.3 预期效果

- 碎片节点（freq=1）从 202 个显著下降，图谱长尾噪声收敛
- SailPoint/网络安全/自动化测试等确定性误归类消除
- 产品经理/项目经理/安全/DevOps/数据科学家/数据库 6 类缺失岗位恢复
- 技能名词不再污染岗位图
