# 技能分类体系评估与优化方案

> 性质：设计类评估文档（评估报告 + 优化方案）
> 关联配置：`backend/configs/skill_whitelist.yaml`（标准技能白名单）
> 关联代码：`backend/app/services/extraction/dictionary.py`（技能归一化）
> 关联数据：PostgreSQL `jd_raw` 全量抽取记录 → Neo4j `Skill` 节点
> 更新日期：2026-08-08

---

## 1. 背景与目的

技能分类体系由 `skill_whitelist.yaml`（592 项标准技能，20 个分类）+ `dictionary.py` 的 `normalize_skill` / `SKILL_ALIAS` / `SKILL_STOPWORDS` 承载：LLM 抽取的 `skill_name` 经归一化后作为 `Skill` 节点入图，用于岗位-技能 `REQUIRES` 关系、技能聚类与技能检索。体系质量直接决定图谱技能节点的纯净度与分类检索的可用性。

本报告基于**真实库全量数据**评估现有分类标准的逻辑性、一致性与实用性，识别归类错误、层级混乱、定义模糊与类型缺失问题，并给出 P0 / P1 / P2 三级优化方案。

## 3. 分类体系问题分析

### 3.2 分类层级混乱（同一技能族拆分到多个类）

- **消息中间件拆分**：`RabbitMQ`(后端)、`Kafka`(大数据)、`RocketMQ/Pulsar/ActiveMQ`(消息/中间件) —— 同类分三处
- **跨端框架拆分**：`React Native/Flutter/uni-app/Taro/小程序/鸿蒙`(前端) vs `移动/桌面`(仅 iOS/Android/Windows 等 7 项) —— 移动开发相关技能分散
- **数据领域拆分**：数据仓库/数据湖(数据库) vs Hadoop/Spark/Flink(大数据) vs HDFS/Iceberg(数据库扩展) —— 大数据生态四分五裂
- **"数据库"与"大数据"边界模糊**：`SQL`(编程语言)、`MySQL`(数据库)、`Hive`(大数据) 各归其位，但 `Elasticsearch`(数据库，实为搜索引擎) 与 `Apache Kafka`(大数据，实为消息中间件) 归类均存疑
- **AI 技能碎片化**：图谱中 AI/Agent 系节点 50+ 个（AI Agent / AI agent / AI Agents / AI智能体 / Agentic AI / Agent / 多智能体 / LLM Agent / AI代理 / AI Coding / AI辅助 / AI编程 ...），白名单只收录少数

### 3.3 类别定义模糊

- **"云原生/DevOps" 45 项过载**：实际涵盖 5 个域（容器/K8s、CI/CD 工具、云厂商、网络基础设施、监控日志），一个类 = 五个子域
- **"工程协作" 17 项名不副实**：JIRA/Kanban 是协作，Maven/Postman/Swagger/Figma 是研发工具，Postman/JMeter 还是测试工具
- **"AI/机器学习" 107 项最大但最杂**：混入嵌入式/自动化测试/多线程/数据分析工具（Pandas/NumPy/Matplotlib 归此类而非数据分析）
- **"音视频" 混入语音 AI**：TTS/ASR/声纹识别是 AI 能力不是媒体处理
- **"网络/协议" 混入无线与定位**：GPS/WiFi/蓝牙 与 BGP/OSPF/HTTP 不是同类
- **软技能类 19 项 vs `SOFT_SKILL_WHITELIST` 20 项**：`数据分析思维` 在白名单归"数据分析/商业"类，不在"软技能"类，但 `SOFT_SKILL_WHITELIST` 包含它——分类与消费集合不一致

### 3.4 类型缺失（高频技能未入白名单）

jd_raw 抽取归一化后**仍白名单外且频次 ≥ 5** 的 416 个技能，累计 4033 次出现。高频典型（括号为出现次数）：

| 类别 | 缺失技能 |
|------|---------|
| 前端 | Vue3(48), ES6(27), ReactJS(13), Element Plus(14), Vue2(21) |
| 后端 | JVM(44), .NET(35), MyBatis-Plus(16), Gin(16), Gradle(16), JSP(15), SpringMVC(22) |
| 协议/接口 | REST API(54), RESTful(17), SQL优化(31), MQ(29), XML(23), MQTT(26) |
| AI/ML | AI Agent(33), NLP(31), Prompt Engineering(29), Cursor(27), Milvus(32), Pinecone(20), SFT(17), CUDA(16), 分布式训练(17), 模型压缩(14) |
| 语义网/知识图谱 | RDF(21), SPARQL(21), R2RML(21) |
| 数据工程 | dbt(15), Databricks(17), 数据处理(32) |
| 开发工具 | GitHub Copilot(16), Dify(17), SVN(14), GitHub Copilot(16) |
| 其他 | 系统(36), 性能优化(33), 面向对象编程(24), 敏捷(21), 低代码(17), 物联网(18), 多传感器融合(18), ROS2(19), 微信小程序(18), 分布式事务(16) |

其中相当一部分是**同义异构/别名缺失**（如 Vue3→Vue.js、NLP→自然语言处理、Prompt Engineering→提示工程、SpringMVC→Spring MVC、微信小程序→小程序、面向对象编程→面向对象），可通过 `SKILL_ALIAS` 归一化，而非白名单新增；另一些是**真实缺失类型**（JVM、.NET、RDF/SPARQL、Milvus、CUDA、dbt、MQTT 等），需新增白名单条目。

### 3.5 同义异构与泛词碎片

- **22 组大小写冲突节点**：`Vue3/vue3/VUE3`、`AI Agent/AI agent`、`AGENT/Agent`、`UniApp/uniapp`、`SpringMVC/SpringMvc`、`npm/NPM`、`pytest/Pytest`、`SQLServer/SqlServer` 等 —— 同名技能在图谱中分裂为多个节点，污染 `REQUIRES` 关系统计
- **泛词/碎片未拦截**（不在 `SKILL_STOPWORDS`）：`系统(36)`、`操作(24)`、`网络(26)`、`前端(25)`、`自动化(23)`、`微(23)`、`嵌入式(22)`、`安全(17)`、`监控(13)`、`数据处理(32)` —— `SKILL_STOPWORDS` 仅 47 词，`微` 已拦截但 `系统/操作/网络/前端/自动化/嵌入式/安全/监控/数据处理` 均未拦截

### 3.6 根因定位

1. **category 字段是"死配置"**：`skill_whitelist.yaml` 为每个技能标注 category，但 [kg_service.py](file:///c:/Users/87088/Desktop/zglp/zhigang-compass/backend/app/services/kg/kg_service.py#L204-L250) 创建 Skill 节点时**不写 category**（schema.cypher 虽声明 `skill.category` 索引，节点属性从未落地）；API `/skill/{id}` 返回的 `category` 恒为空，前端亦不消费。分类体系仅存在于 yaml，未进入图谱与产品链路
2. **白名单以"覆盖广"为先，未做互斥归类**：多个"扩展段"（数据库扩展/AI扩展/后端扩展/前端扩展/数据分析扩展）直接追加，追加时未校验归类互斥性与正确性
3. **归一化覆盖不足**：`SKILL_ALIAS` 仅 42 条，远不足以覆盖 6000+ 抽取变体；`normalize_skill` 对白名单词做大小写归一，但白名单外词原样入图，导致大小写冲突
4. **软技能双轨不一致**：yaml 分类与 `SOFT_SKILL_WHITELIST`（20 项消费枚举域）不同步

## 4. 优化方案

### P0：技能分类落地（让分类体系真正生效）

| 项 | 内容 | 依据 | 预期效果 |
|----|------|------|---------|
| P0-1 | Skill 节点写入 `category`：创建 Skill 时从白名单查 category 写入（白名单外技能标注 `未分类`） | 3.6-1 category 死配置 | `/skill/{id}` 与图查询返回真实分类；分类体系进入产品链路 |
| P0-2 | 重构白名单分类边界：修正 3.1 全部归类错误 + 3.2 同族合并 | 3.1/3.2 归类错误与拆分 | 每类语义互斥，图谱分类可检索 |
| P0-3 | 软技能分类与 `SOFT_SKILL_WHITELIST` 对齐：`数据分析思维` 移入软技能类 | 3.3 双轨不一致 | 分类与消费枚举域一致 |

### P1：归一化补全（消除异构与碎片）

| 项 | 内容 | 依据 | 预期效果 |
|----|------|------|---------|
| P1-1 | `SKILL_ALIAS` 扩充：新增 Vue3→Vue.js、NLP→自然语言处理、Prompt Engineering→提示工程、SpringMVC→Spring MVC、微信小程序→小程序、面向对象编程→面向对象、ReactJS→React、SQL优化→SQL 等 ≥ 30 条 | 3.4 别名缺失 | 高频同义变体归一化到标准词 |
| P1-2 | `SKILL_STOPWORDS` 扩充：新增 系统/操作/网络/前端/自动化/嵌入式/安全/监控/数据处理 等泛词（先验证入图频次后定名单） | 3.5 泛词碎片 | 泛词不再入图，节点纯度提升 |
| P1-3 | 图谱存量去重：合并 22 组大小写冲突节点（Vue3/vue3、AI Agent/AI agent 等），归属最高的规范名 | 3.5 大小写冲突 | `REQUIRES` 关系统计恢复准确 |

### P2：类别重定义（长期治理）

| 项 | 内容 | 依据 |
|----|------|------|
| P2-1 | 拆分"云原生/DevOps"→ 云原生、CI/CD、监控可观测、云厂商 4 个子域 | 3.3 45 项过载 |
| P2-2 | 新增/明确类：消息中间件（收编 RabbitMQ/Kafka）、移动/跨端（收编 RN/Flutter/uni-app/小程序/鸿蒙）、数据工程（收编 HDFS/Iceberg/ETL/数据仓库） | 3.2 同族拆分 |
| P2-3 | "工程协作"改名"研发工具/协作"并重新归位 Maven/Postman 等 | 3.3 名不副实 |
| P2-4 | 建立白名单条目审核规范：新增条目需满足归类互斥 + 消费链路标注（哪些类被图谱/前端消费） | 3.6-2 追加失控 |
