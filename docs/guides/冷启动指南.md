# 冷启动指南

> 从零环境/空库到系统产出可用数据的完整流程。分三个层面：**基础设施启动**（一次性）、**数据冷启动**（一键脚本 + 爬虫前置）、**功能层冷启动行为**（数据不足时的兜底，已内置，无需操作）。
> 设计依据：docs/design/设计文档.md（§4.4 ETL 管线、§7.1 版本管理、§7.2 新岗位发现）。

## 一、基础设施启动（一次性）

```bash
# 1. 起基础设施（postgres / redis / neo4j）
docker compose up -d postgres redis neo4j

# 2. 后端依赖 + 数据库迁移（建 raw 表 / 业务表 / graph_versions）
cd backend
uv run alembic upgrade head

# 3. JWT 密钥（RS256 双 Token；若 .env 已配置可跳过）
uv run python scripts/generate_keys.py
```

- **Neo4j schema**（约束/索引/全文索引/Counter）已内置在数据冷启动脚本第 1 步，也可单独跑 `uv run python scripts/init_neo4j.py`。
- **bootstrap admin**：首次部署 users 表为空时，登录接口按配置自动创建（见 auth.py）。
- **前端**：`pnpm install && pnpm dev`（127.0.0.1:5173）。
- 详细环境步骤见 `docs/guides/团队启动指南.md` 第二部分。

## 二、数据冷启动（核心）

### 前置：采集原始数据

一键脚本不负责采集（爬虫依赖代理/登录态等环境），需先保证 raw 表有数据：

| 数据 | 来源 | 命令 |
|---|---|---|
| JD（岗位） | boss/zhilian/国际源 | `scrapy crawl boss -a keywords=...`（详见 crawlers/README） |
| 课程 | icourse163（直连）/ coursera、edx（需代理） | `scrapy crawl icourse163 -a keywords=...` |
| 论文/社区 | arxiv / github / stackoverflow | `scrapy crawl ...` |

> Windows 运行爬虫需先设 `PYTHONPATH=backend;backend\data`；国际源另设 `HTTPS_PROXY=http://127.0.0.1:7890`。

### 一键脚本（推荐）

```bash
cd backend
uv run python scripts/bootstrap.py            # 全流程
uv run python scripts/bootstrap.py --list     # 查看阶段
uv run python scripts/bootstrap.py --only snapshot  # 只跑单个阶段
```

按依赖顺序执行 8 个阶段，全部幂等可重跑，任一阶段失败即停（fail-fast）：

1. **init_neo4j**：加载 schema.cypher（约束/索引/Counter）
2. **occupations**：导入 O*NET 权威岗位库（1016 职业，新岗位发现 RAG 接地的检索源）
3. **backfill**：jd_raw 剩余记录 LLM 抽取（`snapshot[extraction]` 标记跳过已抽取）+ 课程入图
4. **rebuild**：清空图谱（保留 Counter）并按岗位归一化规则重放已抽取 JD
5. **load_courses**：课程重新入图（rebuild 会清空图谱，课程须在之后恢复）
6. **cleanup**：幻觉技能过滤 + 重复岗位合并 + 重新聚合
7. **evaluate**：课程质量评估（六维加权，写回 `snapshot[quality]`）
8. **snapshot**：发布首期图谱版本快照（`graph_v{YYYYMMDD}`）

> 顺序关键点：`rebuild` 会清空图谱，故课程入图（阶段 5）必须在其之后；`backfill` 阶段 2 的课程入图会被 rebuild 清除，属正常。

### 手动分步（不跑一键脚本时）

按上面 8 个阶段顺序执行对应脚本：

```bash
uv run python scripts/init_neo4j.py
uv run python scripts/import_occupations.py
uv run python scripts/backfill_ingest.py
uv run python scripts/rebuild_graph.py
# 课程入图（rebuild 后）：uv run python -m pytest 无对应 CLI，可执行
uv run python -c "import asyncio; from app.workers.tasks import load_courses; print(asyncio.run(load_courses({})))"
uv run python scripts/cleanup_graph.py
uv run python scripts/evaluate_courses.py
# 快照：uv run python scripts/cron/snapshot_daily.py（需 worker 常驻）或
#       GraphVersionManager().create_snapshot(triggered_by="manual")
```

### 自动化衔接

- 每日 ETL + 快照由外部 cron 触发（Linux `crontab.example` / Windows `scheduled_tasks.ps1`）：
  - `etl_daily.py`（02:00/04:00/05:00 分组）→ 入队 `run_etl_pipeline`（含快照阶段 12）
  - `snapshot_daily.py`（每日 05:00）→ 入队 `snapshot_graph` 发布当日版本
- ARQ worker 需常驻：`uv run python -m arq app.workers.tasks.WorkerSettings`（生产用 `docker compose up -d worker`）。

## 三、功能层冷启动行为（内置，无需操作）

| 模块 | 冷启动策略 | 设计出处 |
|---|---|---|
| 演化信号 | 快照 <2 期不判定；技能频次 <10 小基数保护 → 信号为空（不武断） | §7.1 |
| 新岗位发现 | 无 90 天历史窗口 → 弃 Z-score，走 Wilson score 区间下界（`wilson_lower>0.3` 且源 ≥3 保守入 candidate） | §7.2.4 |
| 课程质量 | 缺失字段给中性分（评分 0.5、未知平台 0.5），不因缺数据误判低分 | §4.6 |
| 简历匹配 | 内容匹配 + Sentence-BERT 语义，刻意不用协同过滤（冷启动严重） | §10 |
| panorama | Redis 30s TTL，首次未命中回源 Neo4j | §11.3.5 |

## 四、验证清单

冷启动完成后确认：

- [ ] `jd_raw` / `course_raw` 有数据（来自爬虫）
- [ ] `occupations` 表 1016 条（`uv run python scripts/import_occupations.py --no-write` 可核对解析）
- [ ] Neo4j 有 Position/Skill/Evidence/Course 节点（Browser localhost:7474 核对）
- [ ] `graph_versions` 存在 `graph_v{当日}` 快照（`GET /api/v1/evolution/versions` 查看）
- [ ] `/api/v1/evolution/signals` 返回 `window_count ≥ 1`（<2 期不产信号，属预期，待每日快照积累）
