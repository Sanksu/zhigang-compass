# 贡献指南

> 本指南规定团队协作纪律与代码提交规范。AI 智能体协作规则详见 [AGENTS.md](../../AGENTS.md)。

## 三条不可松绑的铁律

1. **契约优先**：API 变更必须先改 `contracts/openapi.yaml`（单一事实源），再写后端实现，前端通过 `openapi-typescript` 生成类型，不得自行定义与后端不一致的类型。
2. **main 可运行**：`main` 分支任何时刻都可 `docker compose up -d` 一键启动并通过健康检查，禁止直推，必须经 PR + CI 全绿 + ≥ 1 人 Review。
3. **每日集成**：`develop` 分支每日至少合并一次可运行的功能增量，分支生命周期 ≤ 3 天，超出必须拆分。

## 团队协作规范

- 代码管理：Git Feature Branch 工作流（Trunk-based，分支 ≤ 3 天）
- Commit 规范：`<type>(<scope>): <description>`，type 含 feat/fix/docs/refactor/test/chore
- PR 需至少 1 人 Review 后合并，单 PR 改动行数 ≤ 500 行
- 模型变更（Alembic 迁移）权限收归后端 + 算法负责人

## 分支策略

| 分支 | 用途 | 保护规则 |
|------|------|---------|
| `main` | 稳定版本 | 禁止直推，PR + CI 全绿 + ≥ 1 人 Review |
| `develop` | 开发主线，每日集成基线 | 禁止直推，PR + ≥ 1 人 Review |
| `feature/<模块>-<简述>` | 新功能开发 | 从 `develop` 切出，≤ 3 天合并 |
| `fix/<模块>-<简述>` | Bug 修复 | 从 `develop` 切出 |
| `hotfix/<简述>` | 生产紧急修复 | 从 `main` 切出，合回 `main` 与 `develop` |

模块前缀：`fe`/`be`/`algo`/`data`/`test`/`docs`

## 前端 Mock 优先

前端开发不依赖后端实际可用，基于 `contracts/openapi.yaml` 用 MSW（Mock Service Worker）独立开发：

1. 后端先交付 `contracts/openapi.yaml`
2. 前端用 `openapi-typescript` 生成类型
3. 前端用 MSW 模拟 API 响应，独立推进
4. 联调阶段切换至真实 API

工作流优先级：**测试 > 算法 > 后端 > 前端**（避免前端空等）

## 开发环境

- Node.js ≥ 20.10 + pnpm 9
- Python ≥ 3.11 + uv
- Docker Desktop ≥ 24.0 + Docker Compose v2
- PostgreSQL 15（pgvector 扩展）+ Redis 7 + Neo4j 5（由 Docker Compose 启动）
