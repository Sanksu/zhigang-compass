### 后端正确性

**P1-5 ✅ 启动预热全量加载 JDRaw 无上限** — `backend/app/main.py:133-138`：`select(JDRaw)` 全实体（含 raw_text + snapshot JSONB）`.all()` 一次载入。爬虫持续入库，启动内存峰值/耗时线性恶化，最终冷启动 OOM/超 healthcheck（虽有 try/except 降级，加载本身在最外层之前）。修法：只取必需列或 `yield_per` 分批流式构建池化向量。

**P1-6 ✅ 技能频次窗口缺零填充，current 取错位** — `backend/app/services/evolution/trend_service.py:35-66`：`_skill_freq_windows` 仅在技能当期有边时 append 窗口，中途消失的快照期被跳过；`detect_signals_from_snapshots` 取 `seq[-1]` 为 current → 最新快照已消失技能拿"最后出现期"当当前值，declining 系统性漏检、z 在非连续子序列上失真。同仓 `state_machine.position_freq_windows:87-91` 明确做了全 0 预填并注释"否则窗口错位"，两处口径不一致。**修复语义（消失技能是否按 0 频参与判定）属算法域，须张恺天拍板后动手**。

**P1-7 ✅ BackoffRetryMiddleware 返回 None 违反 Scrapy 契约** — `backend/data/crawlers/middlewares.py:122`：`process_response` 429/403 退避分支 `return None`；Scrapy 下载中间件管理器对非 Response/Request 输出 raise `_InvalidOutput` → 每次退避产生假下载错误：日志噪音、stats 污染、errback 被误触发。数据不丢（`callLater` 已接管重试）。修法：返回挂起 Deferred（`d = defer.Deferred(); reactor.callLater(delay, d.callback, retry_request); return d`）。

**P1-8 ✅ 幽灵 ETL 阶段 `positions_cache_prebuild`** — `backend/app/workers/etl.py:75`：`_FACT_GATED_STAGES` 声明该阶段，但 `run_etl_pipeline` 无执行代码（全库唯一引用即此行）→ degraded 时审计 dict 写入不存在的阶段项，违反「新 ETL 阶段三处同步」纪律。修法：删键或补实现。
