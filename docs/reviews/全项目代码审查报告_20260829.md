## P1（7 项，合入 main 前修复）

### 后端

**P1-1 画像证据与聚合的通胀排除分母口径漂移** — `services/graph/portrait_evidence.py:96-102`
聚合侧 `_inflation_stats` 的 `pos_total` **包含**归档行（主循环里才跳过 `jd_weight==0`，aggregation.py:357-364），而 portrait_evidence 在算占比**之前**已剔除归档行 → 岗位存在归档 JD 时，「通胀占比 ≥30% 全剔除」的触发判定两边可能不同，证据列表与画像条目计数对不上（恰是本功能的核心承诺）。0.30 数值当前与 `_POSITION_INFLATION_EXCLUSION_RATIO` 一致，但属重复硬编码。
修法：分母口径对齐聚合（归档行计入分母），阈值改 import 常量。

**P1-2 jd_admin 绕过 `resolve_operator` 守卫** — `admin_routes/jd_admin.py:160,184`
本 delta 已将全部 admin 写端点收敛到 `api/common.py:142` 的 `resolve_operator`（防 `AuditLog.user_id` UUID 列约束 500），唯当天新增的 jd_admin PUT/DELETE 仍用 `current_user.get("sub") or "admin"` 裸兜底。修法：两处改用 `resolve_operator(current_user)`。

**P1-3 jd_admin PUT 裸 dict 违反契约优先** — `admin_routes/jd_admin.py:120`
`body: dict[str, Any]` 不校验：`{"raw_text": null}` 静默清空正文、无 max_length（可提交数 MB）、`crawled_at` 无格式校验（污染 `parse_crawled_at` 输入）。契约 `JdAdminUpdate` 已声明全 string 字段。修法：定义 Pydantic `JdAdminUpdate`（str + max_length + crawled_at 格式 validator），与其余 12 处 admin 写端点对齐。

**P1-4 guest 可见 candidate 岗位（跨域可见性口径不一致）** — `api/v1/discovery.py:109-110`
`/discovery/recent` 仅对完全匿名过滤 candidate，而图谱域单一事实源 `services/graph/visibility.py` 对 guest 同样走 public scope（candidate 不外宣）。登录 guest 可经 discovery 拿到待审核岗位名与定义草稿。修法：改用 `role_rank` 判定与 `_can_view_all_positions` 对齐；`evolution.py:682-686` 的同款匿名 masking 一并核对。

### 前端

**P1-5 admin-jd 页 openDetail 无时序守卫** — `routes/admin-jd-page.tsx:115-127`
快速连点两行「编辑」时慢响应覆盖新响应；详情加载中关闭弹窗后响应返回会把已关闭的弹窗重新弹开（`open` 条件含 `detailLoading`）。修法：请求序号或 jdId 匹配后再写入。

**P1-6 详情加载失败错误不可见** — `admin-jd-page.tsx:122-123`
失败时 `actionError` 只在弹窗内渲染，而此时弹窗条件不成立 → 用户侧「点了没反应」。修法：失败时用列表级提示或保持弹窗开显示错误态。

### 测试

**P1-7 jd_admin 路由零测试（安全红线缺口）** — `backend/tests/` 全树无 jd_admin / `/admin/jd` 命中
raw 数据编辑/删除 + content_hash 重算 + AuditLog 均无回归防护。同形态可低成本补齐：`tests/admin/test_approval_summary.py` 用 fake async session 直调端点协程，可复制该形态补 list/get/update/delete + RBAC + hash 重算断言。
