## 二、错误形态分析

### 分类（0.8714）
- 弱组集中在同域近邻：编程语言 0.43（JavaScript/TypeScript/Go/Rust 等语言族内部混淆）、大数据 0.71、数据分析/商业 0.71、智能驾驶/机器人 0.71、消息/中间件 0.71、计算机基础 0.71。
- 强组（AI/机器学习、云原生、安全、数据库、网络/协议、测试、软技能、移动/桌面、硬件/芯片、游戏/数字孪生）全 1.0——大类边界清晰时模型可靠；**同域近邻细分类别是量化缺口主源**。

### 归一（merge 0.06——系统性拒绝合并）
- 133 个别名变体（gold=merge 到标准名，如 JS→JavaScript）中仅 ~8 个被 LLM 判 merge，绝大多数判 keep/独立——决策器 prompt 的「短缩写倾向 keep」引导过强，把有权威别名证据的变体也当成独立技能。
- **仅存的 keep 切片 9/10 正确，但 1 个短词被错误 merge（error_merge_count=1）违反「错误合并=0」验收红线**——需定位具体样本并收紧「仅白名单标准名可为目标」硬门或 prompt 明确禁止短词 merge。
- 根因假设：`decide_skill_normalize` 默认候选按长度差排序取前 15，alias 变体与候选标准名相近度不足；prompt 未携带「该变体有别名证据」导致模型保守。

### 关系（precision 0.44，方向 0.99）
- 方向判定极稳（0.99），但关系类型命中差——模型对「先修/父子」的语义门槛把握与 YAML 权威口径不一致（受 0 共现证据输入影响：本评测 evidence=[]，模型在无证据下保守/猜测）。
- **待优化输入**：@eval 未传共现证据（`decide_skill_relation` evidence=[]），真实提案脚本（PR6b）带 {position,count} 证据——生产链路与评测口径不一致，应补证据后复测再判数。

## 三、结论与本批价值

1. **黄金集 + 评测链路本身达标**：确定性 gold 免人工标注，378 次真实调用零失败，逐条 jsonl 落 reports/（可复跑、可 diff 三跑）。
2. **决策器一致性不达标是真实缺口，非观测误差**：归一 prompt 的 keep 倾向需重新校准（对齐别名证据）；关系评测需补证据输入复测；分类需同域近邻类目的 prompt 样板或类目粒度评估。
