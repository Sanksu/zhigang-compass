## 五、main/develop 分叉梳整（08-25）

此前用 squash 合并做 main 同步（#528/#529/#534），squash 不保留祖先关系，导致提交图分叉（`merge-base` 显示从 #482 开始、`mergeable=CONFLICTING`），但**内容层 develop 是 main 超集**（`git diff` 仅 #531/#532 的 4 文件差）。

**终局**：以 develop 为权威，在独立 worktree 将 main 合并入 develop（冲突 normalization_150 / merge_redundant_skills 以 develop 版本解决），再 force 更新 main 指向 = develop 的合并提交（b913a2d）。**main 与 develop 内容完全一致**（diff 空），祖先链已接（b913a2d 的 parent = 4f675ea = develop）。

**核心教训**：合并 develop→main 应使用 `--merge`（保留祖先），不要用 `--squash`（会反复制造分叉假象）。
