- **归一 10 倍改善来自候选召回修复**（r1 根因：gold 标准名 2/60 进候选；r2 召回 93/133）——证实「模型在正确候选下能做对判断」，r1 的 0.06 不是模型能力问题。

## 三、r2 剩余缺口（r3 方向）

### 归一 0.609 → 缺口构成
1. **跨语言召回 40/133 未进候选**：full stack→全栈、llm→大语言模型、rag→检索增强生成、tf/sklearn/pg/es 小写缩写——词面分级排序覆盖不了中英对应与小写缩写（大写首字母串规则只认全大写名）。r3：候选并集补 SBERT 语义近邻（生产链路本就有 SkillEmbedder）或别名表反向索引召回。
2. **gold 歧义（口径可辩）8 例**：c语言→gold C 但白名单另有「C语言」标准名（模型选 C语言 更合理）；spring→gold Spring Boot 但「Spring」也是标准名；sql优化→gold SQL 但「SQL调优」更贴。这类是**别名表与白名单并存的近义标准名**——建议 r3 评测口径加「预测目标与 gold 同为白名单标准名且词面近邻」的容差，或别名表归一治理（同张恺天口径拍板）。
