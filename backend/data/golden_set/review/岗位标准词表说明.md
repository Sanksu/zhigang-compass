# 岗位标准词表（人工标注用）说明

## 词表来源

`岗位标准词表_人工标注用.xlsx` 只整理以下代码中明确写出的静态岗位归一化规则：

- `backend/app/services/extraction/dictionary.py` 的 `_POSITION_KEYWORDS`；
- 同文件的 `_ANALYST_SUB_FAMILIES`；
- 同文件的 `_EN_POSITION_MAP`（英文岗位名到代码中显式目标岗位名的映射）。

词表不新增、猜测或扩展任何项目代码中不存在的标准岗位名。`_TECH_STACKS` 仅用于在归一化过程中拼接技术栈限定词，不把可能动态拼接出的岗位名当作独立静态词表项。

## 当前岗位名称归一化机制

`normalize_position_name` 先尝试英文岗位名映射，再处理中文岗位名的前后缀、关键词族与分析师细分规则：

1. 英文岗位名依次按精确匹配、逗号前主标题、最长子串匹配 `_EN_POSITION_MAP`；
2. 中文名称清理级别前缀、括号内容与可识别技术栈限定词；
3. `_POSITION_KEYWORDS` 按代码列表顺序匹配；
4. 仅名称以“分析师”结尾时，检查 `_ANALYST_SUB_FAMILIES`；
5. 无法命中时，保留代码规则处理后的名称，泛词则不入图。

`PositionAligner.align` 在规则归一化之后，才尝试图谱已有岗位名复用；仅规则未稳定归并且图谱中没有同名岗位时，才以 SBERT 相似度（默认阈值 0.9）进行语义兜底。

## 静态词表的边界

Neo4j 图谱岗位名来自运行中的数据，可能随采集、人工维护或历史导入而变化；SBERT 兜底结果也依赖当时图谱候选和相似度。因此两者不是稳定、可审计的静态标准岗位体系，不能直接写入本词表。

本词表也不替代当前代码逻辑：`priority` 仅展示静态规则的实际检查顺序，帮助人工理解，不改变任何运行时归一化行为。

## review_gold_title 的使用原则

- 优先依据真实 JD 的 `job_title_raw` 与 `detail_raw_text`，尤其是岗位职责；
- 能明确映射到词表时使用对应的 `standard_position`；
- 单个技术词不等于岗位结论，例如出现 Java 不必然是 Java 开发工程师；
- 分析师岗位优先核对 `_ANALYST_SUB_FAMILIES`，并确认正文确实支持该细分方向；
- 大模型、AI、机器学习、NLP、视觉等岗位按现有关键词规则可能归入“算法工程师”，不额外创造新静态类别；
- 词表无法合理覆盖时，暂保留原始或更准确岗位名，并在 `annotation_note` 标记“待岗位体系审核”；不得擅自修改 `dictionary.py`；
- 新岗位是否进入正式标准体系，由项目负责人或算法负责人统一确认；AI 不得替代人工填写 `review_gold_title`。
