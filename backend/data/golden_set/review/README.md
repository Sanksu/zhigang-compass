# JD 黄金集人工复核表（20 条）

本目录仅为人工复核准备材料，不修改原始黄金集，也不产生任何新的 gold 标签。

## 样本选择方法

本次从 `../jd_golden_100.jsonl` 作确定性分层选择，共 20 条：BOSS 10 条、智联 10 条。

- 岗位类型覆盖：后端开发、算法/大模型、全栈、运维、前端、数据分析、测试与大模型评测。
- 学历覆盖：大专、本科、硕士、学历不限。
- 经验覆盖：原字段为空、经验不限、1 年以内、1–3 年、3–5 年、5–10 年、10 年以上。
- 技能数覆盖：从 1 项至 17 项；同时刻意纳入岗位名含多技术栈/促销语、实习岗、职责模板与岗位类型可能错配的样本，便于发现现有自动标注问题。

选取的 ID：`jd_001, jd_003, jd_008, jd_009, jd_010, jd_034, jd_045, jd_064, jd_074, jd_082, jd_012, jd_013, jd_015, jd_021, jd_025, jd_030, jd_036, jd_053, jd_084, jd_091`。

## 文本与现有标签的对照

先以 CSV 的 `original_raw_text` 为依据，逐项对照 `current_gold_*`；`current_gold_*` 仅是待核对的既有标签，不是答案。复核人仅在 `review_*` 列填写自己的结论。

重要数据限制：BOSS 所选行的 `original_raw_text` 来自原有文件的同名字段。现有智联记录的 `original_raw_text` 均为空；为使复核表每行都有既有文本材料，智联行的该 CSV 列逐字镜像了其既有 `raw_text` 字段。该文本只是字段拼接的元数据，不是详情页 JD 正文；不能据此补写正文事实，信息不足时应标为“原文不足无法判断”。

## 六个 gold 字段的人工判断规则

- `review_gold_title`：根据原文职位名称填写规范、单一的岗位名；不要把多岗位招聘帖强行拆成单一职位。
- `review_gold_skills`：仅填原文明确要求、且应视为必备的技术/工具/方法；统一命名，但不得从常识补全。
- `review_gold_bonus_skills`：仅填原文明确表示“加分、优先、可选、了解即可”等非必备技能；原文未区分时可留空并在备注说明。
- `review_gold_experience`：按原文填写经验区间，建议 JSON 形式 `{"min_years": N, "max_years": N/null}`；原文不足时留空。
- `review_gold_education`：仅填原文明确的最低学历要求；不从岗位层级推断。
- `review_gold_core_duties`：仅摘录或忠实概括原文明确职责，建议 JSON 数组；没有职责正文时留空。

## 复核状态

`review_status` 仅可填写以下之一：

- 正确
- 部分错误
- 明显错误
- 原文不足无法判断

`error_type` 与 `review_note` 用于记录问题类别、原文证据位置或无法判断的原因。

## 禁止事项

严禁 AI 自动填写任何 `review_*` 字段、`error_type`、`review_status` 或 `review_note`。这些列必须由人工根据现有文本材料独立填写。
